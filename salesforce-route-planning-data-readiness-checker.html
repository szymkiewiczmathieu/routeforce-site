      What this checks

      Useful signals, not a black-box score.

      The utility deliberately avoids claiming that any record is route-ready or compatible with a specific product.

      • Coordinates: blanks, values outside latitude/longitude ranges, zero pairs and repeated non-zero pairs.
      • Address fields: recognised Billing, Shipping, Mailing, Other or generic address fields.
      • Routing context: GeocodeAccuracy, owner and territory coverage when those headers exist.
      • Output: counts and field names only, plus a local text summary you can download.

      Interpret the result

      A coordinate is not the whole decision.

      Route planning depends on the records you intend to visit, the address source you trust, your territory model and the operational constraints for a field day. This screen helps start that review; it cannot replace it.

      01

      Confirm the address source

      Accounts can carry more than one address. Make sure the export uses the address that represents the visit location, not simply the first address available.

      02

      Sample the map

      Open a representative sample in Salesforce. A pair can be in range and still point to an old address, a postcode centroid or the wrong site.

      03

      Test the field-day rules

      Only then validate visit duration, time windows, breaks, existing Events and territory coverage with the people who plan the work.

      Privacy

      Questions

      Before you inspect an export

      Does the checker upload my CSV?

      No. The selected file is read in browser memory. The checker has no upload endpoint and does not send rows, headers, counts or downloaded summaries to Tourvia.

      Which Salesforce fields does it recognise?

      It looks for common Billing, Shipping, Mailing, Other and generic address headers; latitude and longitude pairs; GeocodeAccuracy; owner; and territory fields. Custom field labels and exports vary, so the recognised category counts are always part of the review.

      Does a clear result prove that records are accurate?

      No. It means the screen found usable coordinate syntax according to the checks shown. It cannot establish that coordinates represent the intended visit location, that a geocode is current, or that a route will be feasible.

      Does this prove Tourvia compatibility?

      No. This is a vendor-neutral CSV data screen. A Tourvia trial evaluates the actual Salesforce objects, configuration and field workflow in your own org.
